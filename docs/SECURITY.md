# Безопасность

Сервис принимает изображения из сети, хранит галерею снимков и работает с
данными городских камер. Ниже — от чего он защищён, чем и как это проверить.
Каждый пункт закреплён тестом (`tests/test_service_security.py`) или
проверен на собранных контейнерах.

## Модель угроз

| Угроза | Защита | Где |
|---|---|---|
| Подложенный файл весов выполняет код при загрузке | `torch.load(weights_only=True)`: распаковываются только тензоры и простые типы | `falcon/extract.py` |
| Запрос на гигабайты кладёт сервис по памяти | лимит тела до разбора JSON: по `Content-Length` и по фактически полученным байтам (chunked); в nginx — `client_max_body_size` | `service/security.py`, `web/nginx.conf` |
| «Бомба распаковки»: PNG в килобайты, разворачивающийся в гигапиксели | `Image.MAX_IMAGE_PIXELS` = 40 Мп, отказ 413 | `service/app.py` |
| Неожиданный формат файла | только JPEG, PNG, WEBP, BMP, остальное — 415 | `service/app.py` |
| Заваливание запросами | ограничение частоты в nginx: 50 запросов/с с адреса, всплеск до 100, дальше 429 | `web/nginx.conf` |
| XSS в интерфейсе | CSP `script-src 'self'`, без inline-скриптов; все строки от сервера экранируются | `service/security.py`, `service/static/app.js` |
| Встраивание интерфейса во фрейм (clickjacking) | `X-Frame-Options: DENY`, `frame-ancestors 'none'` | там же |
| CSV-инъекция при экспорте в Excel | ячейки, начинающиеся с `= + - @`, экранируются | `service/static/app.js` |
| Управляющие символы и мегабайты в метаданных | проверка идентификаторов, метаданные до 4 КБ | `service/schemas.py` |
| Утечка внутренних ошибок клиенту | подробности — в журнал сервера, клиенту — общий текст | `service/app.py` |
| Несанкционированный доступ к галерее | необязательный ключ API `FALCON_API_KEY`, сравнение за постоянное время | `service/security.py` |
| Известные уязвимости библиотек | `pip-audit` по `requirements.txt`: 0 уязвимостей; starlette и python-multipart обновлены | `requirements.txt` |

## Контейнеры

* Наружу открыт только `web` (nginx). Контейнеры `api` и `postgres` доступны лишь
  внутри сети compose, порты на хост не пробрасываются.
* `api` работает от пользователя 10001, `web` — от непривилегированного nginx.
* Файловые системы `api` и `web` — только для чтения; запись — в том с
  данными и во временный `/tmp`.
* `cap_drop: ALL` и `no-new-privileges`: процесс не получает прав Linux и не
  может их повысить.
* Пароль базы и ключ API задаются переменными (`.env.example`), а не лежат в
  коде. Значение по умолчанию годится только для локального показа.
* Образ для пакетной генерации сдачи запускается от root намеренно: он пишет
  в каталог хоста, владельца которого мы не знаем. Сети у него нет, наружу он
  ничего не открывает.

## Данные

* Полный кадр не хранится: в галерее лежат эмбеддинг и миниатюра кропа
  320×240, этого достаточно оператору для сверки.
* Номер не используется, и это проверяется измерением: закрашивание зоны
  номера снижает сходство не сильнее, чем закрашивание любой другой области
  той же площади. Окно сравнения в интерфейсе повторяет проверку для каждой
  пары «запрос — кандидат».
* Любое наблюдение удаляется из галереи методом `DELETE /api/gallery/{id}`.

## Как проверить

```bash
python -m unittest tests.test_service_security    # лимиты, заголовки, ключ, опасные картинки
pip-audit -r requirements.txt                     # известные уязвимости зависимостей
docker compose exec api id                        # uid=10001, не root
curl -sI http://localhost:8000/ | grep -i security # CSP на интерфейсе
```

## Для эксплуатации

Для показа жюри защита настроена так, чтобы решение запускалось одной
командой. В эксплуатации нужно дополнительно: задать `FALCON_API_KEY` и
`FALCON_DB_PASSWORD`, поставить TLS на входе (nginx или балансировщик),
ограничить срок хранения галереи по требованиям 152-ФЗ и регламента заказчика.
