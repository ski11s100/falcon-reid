# Правовые вопросы: персональные данные, защита, лицензии

Система ищет конкретный автомобиль по кадрам городских камер. Технически это
поиск похожих изображений, но по смыслу — отслеживание перемещений машины, а
значит, косвенно и её владельца. Ниже — какие требования к этому применимы,
что уже сделано в коде и что остаётся оператору системы (заказчику) перед
эксплуатацией.

Это инженерный разбор, а не юридическое заключение: перед внедрением его
должен посмотреть юрист заказчика.

## Коротко

| Вопрос | Ответ |
|---|---|
| Номер используется? | Нет. Он размыт организатором, модель дообучена с закраской зоны номера, и это проверено измерением (README, раздел 5) |
| Лица и люди распознаются? | Нет. Модель описывает кузов; людей в кадре она не выделяет и не сравнивает |
| Уходят ли данные наружу? | Нет. Всё работает на площадке заказчика, при запуске контейнер в сеть не ходит (`HF_HUB_OFFLINE=1`), облачных сервисов нет |
| Кто что искал — видно? | Да. Журнал обращений `service/audit.py`: время, действие, адрес, отпечаток ключа, итог — без кадров и векторов |
| Хранится ли всё вечно? | Нет, если задан срок: `FALCON_RETENTION_DAYS` удаляет старые снимки раз в час и пишет об этом в журнал |
| Можно ли продавать как есть? | **Нет** — две модели из трёх предобучены на VeRi-776, доступ к которому дан для некоммерческих исследований (ниже) |

## Персональные данные (152-ФЗ)

**Когда это персональные данные.** Персональные данные — любая информация,
относящаяся к прямо или косвенно определённому физическому лицу (ст. 3
152-ФЗ). Снимок автомобиля без номера сам по себе человека не определяет. Но
результат поиска — «эта машина была у камеры X в 08:14, затем у камеры Y в
08:31» — в связке с данными заказчика о владельце или регулярных маршрутах
позволяет определить человека. Поэтому систему нужно эксплуатировать как
информационную систему персональных данных.

**Принципы обработки (ст. 5) и что сделано:**

| Принцип | Как это устроено в решении |
|---|---|
| Обработка ограничена законной и заранее определённой целью | Сервис умеет только одно: найти машину по кадру. Свободного поиска по времени и месту, выгрузки всей галереи или построения маршрутов по всем машинам в нём нет |
| Минимизация: не больше данных, чем нужно для цели | Полный кадр не хранится. В галерее — вектор из 256 чисел и миниатюра кропа машины 320×240 для сверки оператором |
| Хранение не дольше, чем требует цель | `FALCON_RETENTION_DAYS`: снимки старше срока удаляются автоматически, каждое удаление видно в журнале. Отдельный снимок удаляется вызовом `DELETE /api/gallery/{id}` |
| Точность данных | Система не выдаёт догадку за факт: при сходстве ниже откалиброванного порога она отвечает «совпадений нет», а решение остаётся за человеком |

**Локализация (ч. 5 ст. 18).** Базы данных с персональными данными граждан РФ
должны находиться на территории РФ. Решение разворачивается у заказчика
(`docker compose up`), база PostgreSQL — в том же контуре, и ни один компонент
не обращается к внешним сервисам: ни при работе, ни при запуске.

**Биометрия (ст. 11).** Биометрические персональные данные — сведения о
физиологических особенностях человека, по которым устанавливают его личность.
Система с ними не работает: она не распознаёт лица и не строит признаков
людей. Но в миниатюру кропа может попасть человек рядом с машиной. Поэтому в
эксплуатации стоит размывать людей в сохраняемых миниатюрах. Детектор людей в
поставку не входит, но место для него одно — `make_thumbnail` в
`service/app.py`.

**Уведомление Роскомнадзора (ст. 22)** и назначение ответственного за
обработку — обязанности оператора, то есть заказчика, а не поставщика
программы.

## Меры защиты (ст. 19 152-ФЗ, ПП РФ №1119, приказ ФСТЭК России №21)

Приказ ФСТЭК №21 задаёт состав мер защиты для информационных систем
персональных данных. Базовые группы мер и их реализация:

| Группа мер | В решении | Остаётся заказчику |
|---|---|---|
| Идентификация и аутентификация (ИАФ) | Ключ API `FALCON_API_KEY`, сравнение за постоянное время | Выдать отдельные ключи операторам, при необходимости подключить единый вход |
| Управление доступом (УПД) | Наружу открыт только интерфейс; API и база — во внутренней сети контейнеров | Разграничить роли: кто может искать, кто — наполнять и удалять |
| Регистрация событий безопасности (РСБ) | Журнал обращений: поиск, регистрация, удаление, объяснение, чистка по сроку; ключ пишется отпечатком | Отправлять журнал в централизованную систему и хранить его по регламенту |
| Целостность (ОЦЛ) | Файлы весов загружаются без исполнения кода (`weights_only=True`), файловые системы контейнеров только для чтения | — |
| Защита среды и периметра (ЗИС) | Лимиты размера и частоты запросов, защита от «бомб распаковки», заголовки CSP и запрет фреймов; подробности — [SECURITY.md](SECURITY.md) | Поставить TLS на входе |
| Анализ защищённости (АНЗ) | `pip-audit` зависимостей на каждом пуше в CI | Периодический внешний аудит |

## Защита от злоупотреблений

Главный риск такой системы — не взлом, а использование по назначению против
конкретного человека: найти, где бывает машина соседа или журналиста. Против
этого в решении три меры:

1. **Журнал обращений.** Каждый поиск оставляет запись: кто искал, когда и
   какую машину система нашла. Злоупотребление становится видимым и
   доказуемым.
2. **Ключ доступа.** В эксплуатации поиск без ключа невозможен, а по отпечатку
   ключа в журнале видно, чей это был доступ.
3. **Человек принимает решение.** Сервис предлагает кандидатов со сходством и
   картой внимания, а при неуверенности честно отказывает. Он не делает
   автоматических выводов о людях.

## Искусственный интеллект: этика и прозрачность

Кодекс этики в сфере ИИ (2021) — добровольный, но на него ориентируются
заказчики из госсектора. Что из него закрыто решением:

* **Человек в контуре.** Итог поиска — список кандидатов и вердикт с порогом,
  а решение принимает оператор.
* **Объяснимость.** Для любой пары «запрос — кандидат» интерфейс показывает
  карту внимания Grad-CAM и проверку закраской номера.
* **Честность о пределах.** Режим отказа, разбор характерных ошибок на
  настоящих кадрах ([ERROR_ANALYSIS.md](ERROR_ANALYSIS.md)) и известные слабые
  места: двойники-каршеринг, смена ракурса, ночь.
* **Недискриминация.** Модель сравнивает машины, признаков людей она не
  использует.

## Лицензии и права на данные

| Компонент | Лицензия | Для коммерческой эксплуатации |
|---|---|---|
| Код решения | свой | можно |
| CLIP ViT-B/16 (OpenAI), веса | MIT | можно |
| timm | Apache-2.0 | можно |
| ResNet50-IBN-a (IBN-Net) | MIT; предобучение на ImageNet | обычная практика, но условия ImageNet — исследовательские; стоит проверить юристу |
| PyTorch, torchvision | BSD-3-Clause | можно |
| FastAPI, Starlette, Pydantic, Uvicorn | MIT / BSD | можно |
| PostgreSQL, pgvector | PostgreSQL License | можно |
| nginx | BSD-2-Clause | можно |
| Шрифты Oswald, Golos Text, JetBrains Mono | SIL OFL 1.1 | можно |
| **VeRi-776** | доступ по заявке автору для некоммерческих исследований, без передачи третьим лицам ([EXTERNAL_DATA.md](EXTERNAL_DATA.md)) | **нет без разрешения правообладателя** |
| Датасет конкурса | условия ЛЦТ | по условиям организатора |

**Что это значит на практике.** Для конкурса внешние открытые данные
разрешены (раздел 7 ТЗ, ответ 46), и VeRi-776 использован законно. Но две
модели из трёх (`resnet-v2-veri.pt` и `clip-veri-ours.pt`) предобучены на нём.
Перед коммерческой эксплуатацией нужно одно из двух:

* получить у правообладателя VeRi-776 разрешение на коммерческое использование
  производных моделей;
* или переобучить эти две модели без VeRi-776 — на данных заказчика или на
  датасете с коммерческой лицензией. Рецепт тот же (`falcon/train.py`), а модель
  `clip-ours.pt` уже обучена без VeRi-776 и остаётся в ансамбле как есть.

## Перед эксплуатацией: чек-лист оператора

- [ ] Определить цель обработки и срок хранения, задать `FALCON_RETENTION_DAYS`.
- [ ] Задать `FALCON_API_KEY` и `FALCON_DB_PASSWORD`, выдать ключи поимённо.
- [ ] Поставить TLS на входе (nginx или балансировщик).
- [ ] Направлять журнал обращений (`FALCON_AUDIT_LOG`) в систему хранения журналов.
- [ ] Определить уровень защищённости ИСПДн по ПП №1119 и дополнить меры по приказу ФСТЭК №21.
- [ ] Уведомить Роскомнадзор об обработке персональных данных (ст. 22 152-ФЗ).
- [ ] Решить вопрос с VeRi-776: разрешение правообладателя или переобучение двух моделей.
- [ ] Включить размытие людей в сохраняемых миниатюрах.
