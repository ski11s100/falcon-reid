# Архив предыдущей версии решения

Здесь лежит код версий v1-v4, который заменён конкурсным ядром `falcon/` и
сервисом `service/`. Ничего не удалено: всё можно поднять и посмотреть.

## Почему заменено

**Формат данных.** Половина скриптов работала со структурой
`dataset/<vehicle_id>/<снимки>`, которой в конкурсном датасете не существует.
Реальный формат — плоский каталог `images/` и отдельные CSV с BBox.

**Протокол оценки.** `legacy/app/retrieval.py` считал полный mAP и выбрасывал из
галереи ВСЕ объекты с камеры запроса. Организаторы считают mAP@10 с нормировкой
на `min(n_pos, 10)` и выбрасывают только объекты, у которых совпадают
одновременно `vehicle_id` и `camera_id`. Это разные числа, и сравнивать их между
собой нельзя.

**Модель.** `legacy/models/resnet18-reid-v1-best.pt` — ResNet18 после 200 шагов
обучения батчем 8. Измеренное качество на локальной валидации: mAP 0.081,
Rank-1 0.087 (см. `legacy/metrics.json`). Архитектура чекпоинта несовместима с
текущей загрузкой весов и в образ не попадает.

**Классический дескриптор.** `legacy/app/fingerprint.py` давал mAP 0.026 —
незначительно выше случайного угадывания. Как боевой энкодер не годится, но
остаётся честной точкой отсчёта для сравнения в презентации.

## Что из этого пригодится

* `legacy/metrics.json` — числа baseline для слайда «с чего мы начинали»;
* `legacy/scripts/error_report.py` — генератор HTML-разбора ошибок, идею стоит
  перенести на новое ядро для раздела 10 ТЗ (глубокий анализ ошибок);
* `legacy/app/quality.py` — оценка качества кадра, перенесена в `service/app.py`.
